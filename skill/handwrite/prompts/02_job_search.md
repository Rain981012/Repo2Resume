# 提示词 2: 【短标题，如「职位搜索与匹配打分」】

> **输入:** 【确认后的技能画像 + 用户偏好（城市/远程/职级/应届/薪资/学历等）+ 可选：用户粘贴的 JD】  
> **输出:** 【带评分的真实在招职位列表（最终展示 top5）】

对应 `SKILL.md` Step 3。填完后删掉所有【】。  
参考：`SKILL.md` Step 3；AI 稿（若有）`../prompts/02_job_search.md`。

## 角色

【一句话】例如：招聘匹配分析师，诚实列出缺口，不为凑高分隐瞒 missing skills。

## 第一步: 生成搜索词

【写清】

- 如何从 `primary_direction` / `tech_stack` / Step 2 的概括职位类型生成搜索词？
- `secondary_directions` 是否降权？（例如最多 1 组搜索词）
- 开搜前必须问用户哪些偏好？（城市、远程、职级、应届、薪资、学历硬门槛…）

## 第二步: 搜职位 / 收 JD

【写清，与 SKILL 对齐】

- 最少搜索多少个真实在招岗位？（SKILL 要求 ≥20）
- 时效？（如优先近 3 个月）
- 缺完整 JD 的条目如何处理？（丢弃 / 降权）
- 用户粘贴的 JD 如何纳入打分池？

## 第三步: 打分

【写出 1–10 分规则】建议覆盖：

- 与 `primary_direction` 一致时的基线分
- 仅命中 secondary 时的基线分
- 画像完全无证据支撑核心要求时的上限（应很低或不推荐）
- `missing_skills` 是否**强制**列出

```json
{
  "title": "...",
  "company": "...",
  "url": "...",
  "score": 0,
  "matched_skills": ["..."],
  "missing_skills": ["..."],
  "verdict": "一句话：为什么该投/不该投"
}
```

【把上面改成你的最终 schema，可增删字段】

## 与用户的交互

【写清】

- 如何展示排序结果？（展示 top5 还是 top5 + 可展开更多）
- **⏸** 用户选定目标职位之前，能否进入简历写作 Step 4？
- 用户多选目标职位时怎么处理？
