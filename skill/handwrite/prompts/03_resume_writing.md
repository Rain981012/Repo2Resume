# 提示词 3: 【短标题，如「亮点挑选与简历写作」】

> **输入:** 【技能画像 + 目标 JD + `stats.json` 事实清单】  
> **输出:** 【按模板组织的 Markdown 简历草稿（项目 bullet 带溯源）】

对应 `SKILL.md` Step 4。填完后删掉所有【】。  
模板：`templates/resume.md.j2`（相对 skill 根目录）。

## 角色

【一句话】例如：技术简历写作者，只重组事实、不发明成果。

## 挑亮点

【写清选择标准】从 `highlights_pool` / 统计中选项目时：

- 与 JD 技术栈重合度
- `author_share` / 个人主导程度
- commit 体量与活跃周期
- 选几个项目？每项目几条 bullet？（SKILL 倾向按 JD 写 4–5 条最相关经历）
- 宁缺毋滥还是必须凑满？

## 写作规则

### 事实约束（最高优先级）

【必须写明】

- 溯源注释格式（应与 SKILL 一致：`<!-- src: 仓库, 依据 -->`）
- 哪些数字能写（仅 stats 或用户亲口提供）
- 缺数字时：问用户 / 留空 / 禁止用假百分比？
- 个人信息（姓名/教育/工作经历）从哪来？可不填时如何用占位符？

### 风格

【写清】

- 动词开头、长度、条数
- 如何自然嵌入 JD 关键词（**仅限有证据的技能**）
- 中英文偏好（若有）

## Few-shot（建议自己写 1 好 1 坏）

**输入统计（简写）**  
【自己编一个贴近你项目的迷你 fact sheet】

**好的输出**  
【合法 bullet + 溯源】

**坏的输出（标明违规点）**  
【例如编造 P99、用户量、或把低 author_share 写成独立主导】

## 填模板

【写清】

- 使用 `templates/resume.md.j2` 的哪些章节
- 项目排序规则（按与 JD 相关度）
- 写完后必须进入 `04_critic_review`，最多几轮？
