# 提示词 4: 【短标题，如「简历审稿 Critic」】

> **输入:** 【简历草稿 + `stats.json` + 目标 JD】  
> **输出:** 【结构化审稿意见：必须修改 / 建议修改 / 通过项】

对应 `SKILL.md` Step 4 自查。填完后删掉所有【】。  
**重要：** 审稿视角必须与写作者（03）分离，不要沿用「帮我润色得更好」的口气。

## 角色

【写清双重视角】例如：挑剔的技术面试官 + ATS 关键词检查；任务是找问题，不是重写全文。

## 审查清单

### A. 事实（可一票否决）

【勾选式条目】至少覆盖：

- [ ] 每条 bullet 的 `<!-- src -->` 能否在统计中找到对应依据？
- [ ] 每个数字是否有出处？
- [ ] 是否夸大多人仓库中的个人贡献（对照 `author_share`）？
- [ ] 【你还可以加】

### B. ATS / 相关性

【勾选式】至少覆盖：

- [ ] JD 核心关键词（有证据支撑的）是否出现？
- [ ] 是否存在与 JD 无关、应删减的段落？
- [ ] 项目排序是否按相关度？

### C. 表达

【勾选式】至少覆盖：

- [ ] 空话（「精通各种」）？
- [ ] 动词开头、长度是否合规？
- [ ] 中英文混排是否符合约定？

## 输出格式

【规定结构】例如：

```text
### 必须修改（阻塞）
1. [事实] …

### 建议修改
2. [ATS] …

### 通过项
- …
```

【写清】

- 写作者根据「必须修改」修订
- 审稿–修订循环最多几轮？（SKILL：**≤2**）
- 2 轮后仍有分歧时如何处理？（交给用户裁决）
