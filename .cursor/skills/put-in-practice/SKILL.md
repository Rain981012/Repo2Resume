# Put-in-practice 复盘更新

用户用 `docs/put_in_practice/` 记录开发过程中的学习与面试复习材料。  
本 skill 规定：**如何更新这些文档**，尤其是**同一 Phase 文档的增量补全**。

## 何时启用

用户说类似：

- 「更新 put_in_practice」
- 「复盘一下刚做完的 prompts / A1 / A2」
- 「把这一步补进 `01_phase_a1_skill_prototype.md`」
- 「查漏补缺实践笔记」

## 硬性规则

1. **先读后写**：打开目标文档（及同 Phase 相关文件）全文或相关章节，再改。
2. **查漏补缺，禁止整篇重写**：已有正确内容保留；只增补缺失、修正过时状态表、追加新坑/新知识点。
3. **一次只服务「本步」**：以用户点名的完成项为准（如「完成了 Phase A1 的 prompts」），不要把未做的 Phase 写成已完成。
4. **语气**：第三人称或「你」皆可，但保持与现有文档一致；面向**面试复习**，可带一句话面试话术。
5. **路径约定**：
   - Phase A → `docs/put_in_practice/PhaseA/`
   - 文件名：`{序号}_phase_{id}_{短名}.md`（已有则用已有）
   - 新建文档前先问用户确认文件名；默认优先改已有文档。

## 每次更新必须覆盖的三块（用户的核心要求）

无论新建还是补同一文档，本步内容都要能在文档里找到对应：

### ① 本步完成了什么

- 用清单或表格更新「对照 MVP / 当前状态」
- 写清交付物路径（如 `skill/prompts/01–04.md`）
- 区分：**搭建完成** vs **验收/真跑尚未做**

### ② 做了什么 · 对项目的影响 · 亮点 · 踩坑

至少回答：

| 子问题 | 写什么 |
|--------|--------|
| 做了什么 | 具体动作（手写/同步/改规则…） |
| 影响 | 对 Skill 行为、后续 Phase、验收标准的影响 |
| 做得好的 | 1–3 条可上面试的设计点 |
| 踩坑 | 现象 → 教训 →（可选）面试升华；新坑用「坑 N」追加，不删旧坑 |

### ③ 本步涉及的知识点（面试可能问）

- 补「知识点表」或 FAQ 条目
- 每条：**概念名 + 你在本项目里怎么练到的 + 可背的一句定义/对比**
- 优先关联本步真实决策（如：多角色 ≠ 多智能体；曾出现 handwrite/正式双路径未同步等）

## 操作流程（Agent 逐步执行）

```text
1. 确认本步范围（用户刚完成的事项 + 目标文档路径）
2. 读目标文档；列出「已有 / 缺失 / 过时」三点简报（可对用户展示后再改，或直接改）
3. 按三块查漏补缺：
   - 更新状态表与「下一步」
   - 在「做得好的 / 踩坑」追加本步条目（不重复已有坑，可交叉引用）
   - 在「知识点 / 面试问答」追加本步相关题
4. 若同文档已有章节：优先在原章节下追加小节，保持原目录结构
5. 改完后用 3–5 条 bullet 告诉用户：改了哪些节、建议下次触发语
```

## 同一文档增量示例

用户：「我完成了 prompts，更新 `PhaseA/01_phase_a1_skill_prototype.md`」

应做：

- ✅ 状态表：`skill/prompts/` → ✅ 已定稿并启用  
- ✅ 追加「四组提示词要点」表（若无）  
- ✅ 追加坑：曾出现 handwrite/正式双路径（现已删 handwrite，只维护 `skill/prompts/`）  
- ✅ 知识点：Skill 加载路径、Writer-Critic 同会话 vs 多智能体  
- ✅ 「下一步」改为 Phase A2  
- ❌ 不要删掉早期关于 `git_stats` / SKILL 定稿的内容  
- ❌ 不要整文件换成新模板

## 新建 Phase 文档时

若用户明确要新文档，使用骨架（可裁剪）：

```markdown
# Phase {X} 实践复盘：{标题}（面试复习稿）

> 项目：Repo2Resume  
> 阶段：…  
> 对应：`MVP_PLAN.md` …

## 1. 一句话定位
## 2. 本阶段完成了什么（对照计划）
## 3. 做法 · 影响 · 亮点 · 踩坑
## 4. 本阶段知识点（面试向）
## 5. 下一步
## 6. 30 秒速记卡
```

然后把用户本步的三块填进 §2–§4。

## 与对话上下文

优先使用**当前对话**里刚发生的决策与文件变更；必要时用 git diff / 读相关源文件核对，避免复盘与代码脱节。
